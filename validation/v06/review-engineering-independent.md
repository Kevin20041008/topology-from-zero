## 覆盖空间的数学与教学模型

1. 采用 $p(u)=\exp(2\pi iu)$；每个相邻样本定义短弧，而非推断未采样鼠标轨迹。对数学上对径的端点，短弧不唯一，要求中间点正确。
2. 命题 L1 的候选区间、半整数排除、分段仿射提升及连续整数值差函数给出的唯一性论证成立。
3. 整数层平移不改变绕数，闭路反向绕数变号，拼接绕数相加，已指定短弧的中点细分保持几何提升；正文六道题的论证与模型一致。
4. `0,0` 定义常值路径，但不能从这种稀疏观测否定真实运动曾绕圈。实验明确区分输入模型与物理轨迹。
5. 两个半圈示例不是闭路，正文没有把提升位移 $\pm1/2$ 称为绕数。闭合依赖实际输入端点，不依赖终点显示的六位舍入。

## 已发现并修复：整数层改变短弧判定（P1）

旧实现先计算 `floor(previous)+sample` 再作差。对于 `s=0.5-2**-54`，`liftPath([0,s],0)` 正常，而起始层为 `-1`、`1`、`1000` 时错误报对径；半圈另一侧 `0.5+2**-53` 也有同类问题。层选择事件又未捕获此异常，会造成 UI 状态与图像不一致。

当前修订保留独立的整数 `sheet` 与原始圆周样本 `turn`，先决定短弧分支，最后才合成浮点绘图坐标。层选择先验证并捕获错误，失败时恢复选择器。已独立执行半圈两侧乘五个起始层的10组回归：全部通过；各层归一化状态相同，闭合路径绕数均为0。增加整数后短分数在绘图坐标中可能不可见，但不会再修改保存的 `turn` 或已闭路的整数绕数。

## 后续发现并修复：相减误判与规范化假闭合（P1）

以下不是使用容差造成，而是浮点算术的具体反例；不应以已有测试通过掩盖。

1. **相减舍入形成假对径。** `liftPath([0,2**-55,0.5])` 中，两个已存储圆周数的实数差严格小于半圈，但 JavaScript 的 `0.5-2**-55` 舍入为 `0.5`，中间修订版仍错误报数学对径。
2. **规范化吞掉负的极短运动。** `projectTurn(-(2**-60))` 中 `rest+1` 舍入成1，再被改成0；随后 `liftPath([0,s])` 被标成闭合。保持原始样本的严格闭合判断不能纠正规范化已经发生的信息丢失。

最终修订已处理两条：

- 半圈比较按每个 binary64 的精确值执行。非负正规数的值为 $(2^{52}+f)2^{E-1075}$，因此以 $2^{-1074}$ 为单位的整数为 $(2^{52}+f)2^{E-1}$；次正规数对应整数 $f$。源码的位解码、指数移位、`HALF=1n<<1073n` 与此一致。有效输入已排除负数、非有限数及1；负零与零均解码为0。整数差恰为正负 HALF 才拒绝，其他情况严格选短弧，不加入容差或量化。
- 规范化若舍入到端点1则抛出说明数值表示限制的 `RangeError`，不会转成0。`appendTurn` 在改变路径前捕获；指针、步进按钮及键盘三个数值入口均经过此函数。层选择同样先验证。闭合按钮明确追加0，是用户定义的新路径段。
- 正文已写清保存状态、整数判定、浮点角度与绘图的区别，以及无法规范化时拒绝输入并保留路径。
- 修订后9项覆盖测试通过。另用 Python `Fraction.from_float` 独立解析已存储数，核对29个边界值的全部有序对与5个整数层，共4205案例；其中20个精确对径案例均拒绝，其他4185个层状态及原始样本全部精确一致。该参考实现没有使用生产代码的位解码函数。

29个数来自0、最小正次正规数、最小正规数、$2^{-60}$、$2^{-55}$、$2^{-54}$、1/8、1/4、1/2、3/4及1的前驱，并加入各自朝0和1的相邻浮点数，去重并限制在 $[0,1)$。整数层为−1000、−1、0、1、1000。该有限对照支持实现检查，不代替上面的表示公式推导，也不证明未采样实际轨迹可恢复。

## 已发现并修复：页面身份缺失（P2）

旧部署检查只比较 commit、清单摘要及 dirty。独立 mock 让全部页面 URL 返回同构建首页 HTML，旧版7个请求仍全部通过；这能检验版本，但不能确认章节 URL 返回对应章节。

当前构建静态写入 `topology-page-path`，来源为 `page.file.src_uri`；检查器按10个请求路径核对对应源文件身份，另记录 HTTP 最终 URL。原反例重新执行后，首页被接受，其余9个错误章节响应全部被拒绝，错误均定位到 `topology-page-path`。同版本首页不能再冒充章节。

## 构建身份与发布流程核对

- `on_config` 一次捕获源码 commit、dirty 与清单摘要；每份 HTML 静态写入该构建身份，无 JavaScript 也可辨认。不会用随后请求到的新清单替旧 HTML 重新打版本标签。
- 前端只在 HTML 与 JSON 不一致时追加警告，保留静态构建标签。检查器拒绝缺失或重复身份、旧 HTML 配新清单、旧清单配新 HTML，以及发布时 dirty。
- 清单摘要对应注册清单，不是每篇正文的内容哈希；本地同 commit 的不同 dirty 构建不能据此区分。`--allow-dirty` 仅用于本地，正式发布要求 clean。
- PR 工作流运行构建与检查；部署仅适用于 main 且依赖 build、learning-project、image-project。部署后核对该次 `github.sha`，保存核验 JSON；不是只凭 Pages action 的成功就称线上一致。
- 普通 URL 请求不添加 cache-buster，最多16次、45秒间隔，以检查公开缓存传播。10个页面是有限抽样，不能代表全站每个页面或所有 CDN 地区。
- 版本与路由身份校验不是数学正确性证明，也不是防恶意服务端篡改的内容认证。

## 保留的限制

- 鼠标角度、规范化及SVG坐标仍有浮点近似，极短运动可能无法在屏幕分辨率中显示；精确比较的是被接受的已存储样本，不能恢复未输入或被拒绝的轨迹。
- 极小负角规范化拒绝是明确的数值输入范围限制，不是宣称该数学路径不存在；真实对径拒绝则是短弧模型不唯一。两种原因已分开。
- 浏览器数值入口的异常捕获在本次以源码路径审阅核对，未另行占用集成浏览器服务注入极限事件；实际浏览器整体行为由根代理检查。
- 发布核验是10页与当前响应的有限抽检；全CDN、全站内容一致性及人类数学审稿仍不在本报告完成范围。

全仓浏览器、严格构建和实际 CI 由集成阶段执行，本报告不冒称已经独立运行这些全套检查。
